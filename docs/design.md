# 《羽与潮》游戏界面规范

**湿地航记**以水彩迁徙场景为主。标题与物种选择沿用晨雾和三种栖息地。飞行界面用纸色读数、深墨提示和少量暖金标记帮助玩家观察航线、处理危险、接应同伴。改版依据见 [UI 审计](UI_AUDIT.md)、[GDD v2.0](../Feather_Tide_Gameplay_Design_v2.0.md)、[TDD §9](../Feather_Tide_Threejs_TDD_v1.0.md) 和 [双手原型](adr/009-dual-hand-camera-controls.md)。

## 视觉令牌

`src/app/ui-tokens.css` 是共享令牌的入口。组件使用语义令牌。限定在特定生境的艺术色与物种读数可以有更窄的作用域。

| 类别       | 令牌及应用                                                                                                                                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 墨色和纸色 | `--ink` #243A32、`--ink-deep` #192D26 用于正文和强标题。`--paper` #F4E9CF 用于暂停、工具和结果，`--cream` #FFF5DF 用于浅底及深色界面的文字。                                                                                            |
| 航标语义   | `--surface-danger` #382B23 和暖金三角表示硬危险。接应用深墨卡片、菱形与暖金世界标记，航线及补给用纸色标签和边线。体力的常态、偏低、危急、恢复分别用独立条色，状态文字同步出现。                                                         |
| 字体及字号 | `--font-ui` 使用苹方 / Noto Sans CJK SC / 系统无衬线。宋体 / Noto Serif CJK SC 用于地名、标题和抵达人数。正文 16px，说明 15–16px，决策主提示 18–22px，关键世界文字 14px，标题约 25–34px，抵达人数 20–27px。变化中的数字用等宽数字特性。 |
| 间距及白边 | 4、8、12、16、20、24 CSS px 为 16px 根字号下的基础间距。纸面 5px 圆角，航标和小控件 3px，胶囊形与圆形用于入口或经常点按的工具。                                                                                                         |
| 透明与遮罩 | 说明纸片约 96% 实色，危险和接应用实色承托短句。通用遮罩约 40%，宽屏暂停和失败从侧边淡出，抵达遮罩约 27% 起并渐隐。锁定物种状态保留文字对比，常规禁用按钮使用 55% 不透明度。                                                             |
| 操作尺寸   | 暂停、镜头复位、滑轨、选择器和辅助操作至少 44 CSS px。放大开关把顶角工具增为 52px，能力键约由 73px 增为 90px。                                                                                                                          |
| 层级       | 世界标记与摇杆层 1，读数与手势提示层 2，工具层 3。系统模态使用原生 `dialog` 顶层，与 Canvas 交互隔离。                                                                                                                                  |
| 动效       | 控件色、边和阴影状态为 120ms，打开面板为 180ms。游戏的「减少动态」和系统 `prefers-reduced-motion` 都能使 UI 动效归零。队形、体力和救援可直接读到实际状态。                                                                              |

色彩验收以普通文字对比度 4.5:1、关键图形 3:1 为检查起点。叠在画布上的透明界面按实际合成背景复核。风险、队伍状态及接应动作同时有文字、形状或进度反馈。 [令牌](../src/app/ui-tokens.css) · [基础组件样式](../src/app/style.css)

## 组件与交互

| 组件             | 规范                                                                                                                                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 行动按钮         | 主要动作使用实色，返回与辅助动作用描边或低强调样式。共享 CSS 提供常态、鼠标悬停、按下、键盘焦点、禁用反馈。触屏不使用悬停表达必要信息。锁定生物保留锁形和开放状态，载入时选择区发布忙碌状态。                               |
| 能力键           | 雁结阵、鲸下潜、鹿等候复用圆形键和进度环，分别使用物种图形与动态文字。保持或切换配置、键盘绑定、指针捕获与模拟代价沿用现有契约。                                                                                            |
| 章节与旅程入口   | 标题保留「进入游戏」。雁的入口说明本次带队目标。有效检查点使「继续 · 芦苇洲」成为主动作，重新起飞在明确选择后开始。完成记录可查看上次落脚。读档失败或存档损坏时，显示返回与明确的重新出发动作。鲸、鹿的状态由构建开关给出。 |
| 暂停与帮助       | 通用面板先显示地点、当前阶段或接应时间，再给继续、设置、飞行操作和返回。教学帮助可回看，当前教学也可从帮助内略过。设置弹窗关闭时回到来源控件。                                                                              |
| 设置             | 固定返回和操作、镜头、舒适性、键鼠四个可聚焦的跳转按钮。内容区独立滚动。触控设置先呈现，宽幅鼠标环绕和键位放在键鼠区。用原生输入和选择器保留读屏与键盘交互，灵敏度显示数值倍数。                                            |
| 失败、演出与抵达 | 失败用短句明确体力耗尽或接应时间已到，并显示可重试地点。落脚暂停中的激活键作用于当前按钮，跳过由明确的界面动作触发。抵达先聚焦标题，再让玩家自行选择返回或重试保存。地点、全队人数和经过路线按顺序展示。                    |

## 飞行布局与信息顺序

### HUD 精修方案 · 2026-11-21

采用改版前的两张 568×320 横屏 WebKit 实景作底稿。S0 镜像起飞时，水道居中，雁群在中下方，地名卡、跳过按钮和手势胶囊先后落在玩家前方视线内。S4 风机与两只离队同伴并发时，扫掠轮廓贴着上缘，接应圈在画面左下方。这个视角需要尽量短的顶部提示，让扫掠边界与接应位置同时可见。 [S0 基线](ui-system/hud/before-s0-568.jpg) · [S4 基线](ui-system/hud/before-s4-568.jpg)

| 画面位置   | 内容和出现时机                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 移动侧角落 | 暂停与窄体力读数。宽屏并排，短屏把体力移到暂停下方。正常体力保留百分比与细刻度，危急、偏低、恢复立即加文字。                           |
| 上缘提示区 | 危险在上，接应紧随其下。危险、接应、补给抉择与等待抵达维持至当前条件解除。教学只显示当前动作，跳过入口贴着说明。                       |
| 左右操作区 | 移动侧只在触摸时绘制浮动摇杆。首次起飞、首次观察在对应侧给出短暂风痕提示，最多约五秒。观察侧上角复位、下角能力，镜像时与暂停一起换边。 |
| 航线和队伍 | 地名短暂淡出。普通巡航把中心留给水道和队伍。世界方向保持可穿透触控，并沿用危险、接应、领队及控件的标记避让。                           |

采用湿地深墨、旧纸色和少量暖金色。角落工具保留原点击范围，缩小肉眼看到的轮廓。结阵以飞雁弧线和实际成阵进度表达。验证使用同一风场夹具比较前后画面，并检查 480×270、手机横屏、平板和桌面视口的裁切、镜像与手势。

- 世界标记使用场景投影。避开 HUD、工具、摇杆和领队投影附近，空间不足时优先压缩为方向箭头或收起次要标签。风机绕行与队尾接应使用原有目标。危险播报补充外侧航道方向或山口与长湖的取舍；接应播报包含方向和时间阈值，秒数及百分比继续在画面中更新。
- 安全区使用浏览器 inset 与基础留边。浮动摇杆图形夹到安全区内，推程及世界映射依据原始触点。短横屏的决策提示依次排在上缘，568×320 风场并发场景的提示区以 100px 为回归上限。减少动态时地名和手势提示直接退场。
- 宽度至少 700px 的横屏暂停和失败偏侧展示，留出队伍和栖地。触屏转竖屏时沿用明确恢复的暂停流程。

## 实现边界

`index.html` 提供原生语义与稳定控件标识，`style.css` 负责共享界面和物种基础样式，`flight-hud.css` 负责雁航行槽位及触控提示。由 `main.ts` 消费模拟快照、事件和已有指引结果，`goose-hud.ts` 派生体力显示与相机相对方向。偏航、危险几何、接应目标、落脚全员谓词和存档读写仍使用现有权威逻辑。读屏信息由可见提示的同一数据生成。

横屏改动主要由 [输入与界面 E2E](../tests/e2e/flight.spec.ts)、[并发提示和落脚 E2E](../tests/e2e/recovery.spec.ts) 以及 [入口 E2E](../tests/e2e/species-entry.spec.ts) 覆盖。完整实机验收继续使用 [设备与首航执行单](plans/goose/execution/playtest-handoff.md)。
