# 01 · 鲸原型共享接口

下列为原型接口建议及验收契约。示例类型名、配置键和值用于对齐，实施时以评审结果为准。现有 `GameRuntime` 固定步长流程可复用，`world.ts`、关卡校验、HUD、场景装配及存档还有雁专属字段。先用鲸真正需要的差异确定边界。

## WH-C01 · 物种状态、移动与队伍

**依赖与交付。** 模拟负责人维护 `GameState`、角色类型、初始化及 tick 入口。先交付雁与鲸各一个快照样例、一份物种配置和固定世界输入样例。W0 消费此接口。

- [ ] 以物种作为状态与配置的判别字段。共有角色记录保留稳定 ID、XZ 位置、朝向、速度、跟随状态和救援进度。`actors` 是领队与同伴的权威名单，按物种配置校验出生、读档及通关人数，雁 12、鲸 6。结阵成形度、空中状态归雁；鲸深度、呼吸与浮潜过渡归鲸。
- [ ] 鲸策略接收世界移动向量和能力状态，输出限速转向、推进和惯性滑行。松手后沿实际轨迹减速至悬浮，途中继续执行碰撞。跟随使用稳定成员 ID，保持可测的转向、间距与追赶速度。
- [ ] 每只鲸都有权威层 `surface | shallow | deep`、过渡方向与进度。原型建议每只鲸各自按层消耗及恢复呼吸，HUD 常显领鲸余量，同伴换气需要通过队尾提示表达。让同伴按可配置延迟跟随浮潜，以自身水层判定碰撞；测试队伍跨层时船离场与汇合行为。
- [ ] 60 Hz 模拟依配置推进下潜、上浮、呼吸与耗尽上浮。建议按住约 1 秒到浅潜，再约 2 秒到深潜；满呼吸浅潜约 40 秒、深潜约 20 秒；水面恢复。耗尽后进入渐进上浮，持续按住时上浮优先。重新下潜的解锁条件作为 W0 调参项，验收需覆盖按住耗尽、抵达水面及再次按键。任务记录实际采用的阈值、上浮用时和恢复门槛。
- [ ] 单测覆盖到达深度阈值的前一 tick／当 tick、短按、反复按放、下降途中释放、上浮途中重按、跨层耗气及耗尽优先级。相同世界输入在 30／60／120 FPS 帧计划下重放到同一 tick，比较位置、能量、凝聚、逐鲸呼吸／深度与事件。

## WH-C02 · 关卡 Schema、深度几何与船舶时序

**依赖与交付。** 关卡负责人维护 `LevelSchema`、加载器、共享校验和 `public/levels/` 数据。产出一份鲸样图和非法数据夹具；W1、W2 最早使用深度几何。

- [ ] 版本化定义物种、出生点、W0–W4 段落、深度层、稳定 Zone／触发器 ID、航道 ID、换气水域和检查点。路线 ID 由对应关卡声明和校验，保留旧雁的 `mountain`／`lake` 语义。鲸试用 `shipping`／`quiet`；在实际越过路口时记录，在汇合区锁定，回到分岔前检查点后可重选。
- [ ] 船和网由 XZ 轮廓、`depthMask`、警告关联和危险效果定义。W1 单船初值占水面和浅潜；W2 网具覆盖三层；W3 噪声作为跨层干扰区。移动船的航向、路径、周期与相位基准由 tick 和关卡参数确定，供判定和表现同源采样。
- [ ] 提交明确的层切换边界约定。建议在切层的固定 tick 边界统一提交新层，切换前的扫掠使用旧层，切换坐标使用新层判定；移动船按同一时间区间做相对扫掠。用切层与接触同 tick、快速相向、网口角点和强制上浮到船层的夹具证明判定一致。渲染可插值 Y，标签和轮廓指明模拟当前层与过渡方向。
- [ ] 校验未知物种／版本／深度位、空危险掩码、坏几何、重复 ID、无效周期、无效路线及关联缺失。以共享校验器执行运行时加载和命令行校验。旧雁 JSON 仍可按原数据读取；加载错误含关卡 ID 与字段路径并提供重试入口。

## WH-C03 · 输入、镜头、HUD 与音画消费接口

**依赖与交付。** App、输入与表现负责人共用 `WorldInput` 和只读快照／事件。W0 验证接线，W1／W2 验证遮挡。菜单开发入口通过明确的开发构建配置开启。

- [ ] 继续使用 `WorldInput.move`（世界 XZ）与 `ability`，由当前物种解释能力。触点在按下时领取固定职责；维持左移＋拖镜与左移＋能力；桌面沿用可改键的移动、Space、复位与暂停入口。按住和点按切换共用同一浮潜状态机。
- [ ] 镜头的拖动、复位、观察范围和默认构图由表现层处理。A 实时映射、B 按下锁定基准，用 W0 和 W1 对照。相同世界输入序列分别重放正常、拖镜与复位，比较完整模拟快照。失焦、点击暂停、横竖屏变化、后台及 WebGL 中断沿用统一释放与显式继续流程。
- [ ] HUD 读取当前层、过渡方向、呼吸余量、换气方向、风险占用层、救援方向与实际到达人数。示例文字为「浅潜 · 正在下潜」「呼吸偏低 · 前方可换气」；用文字／图形配合风格色提示。回望仍保留危险方向；标准和低画质共享风险轮廓。
- [ ] 用模拟快照提供鲸的位置与层、船在对应 tick 的姿态、网具轮廓及事件。Y 插值、模型动画、音量转场、雾和水纹由表现决定。先用灰盒校准海面与鲸长，再试 `WL-CHR-001` 和《Deep Blue Drones》；以灰盒回放复测遮挡、加载及静音可玩。

## WH-C04 · 旅程、救援与汇合

**依赖与交付。** 复用 `ModeRules`、补给／安全区及已有救援状态流转。定义鲸的接应资格、检查点资格和到达谓词，由 W2／W4 测试。

- [ ] 旅程危险接触产生阶段性后果，失败来自安全区外能量归零或救援超时。呼吸耗尽进入上浮，安全区可停留换气及观景。依据 ADR-010 隔离旧漫游存档。
- [ ] 接应从稳定成员 ID 和实际位置计算。W2 原型以网外可达、同层、低速停留为候选接应条件，倒计时约 40 秒、停留约 2 秒取作初值。验收记录错误水层、超速穿过、折返及接应完成，归队依跟随运动回槽。
- [ ] HUD 和汇合锁定消费同一个逐成员就绪谓词。鲸须在目标区、位于水面且已完成上浮，跟随状态为 `following` 或 `loose`；停泊是否另需低速门槛由 W4 试玩决定。全队满足才进入汇合阶段并冻结模拟，同一次航程仅生成一份结果。检查点单独按安全水域里的全队就绪条件触发，和终点使用相同角色名单。

## WH-C05 · 检查点、存档隔离与旧档

**依赖与交付。** 保存负责人维护 `CheckpointSnapshot`、`RunRecord`、App 恢复与 `SaveStore`。交付 C1／C2 快照样例和旧雁存档兼容夹具。

- [ ] 以物种＋关卡 ID＋模式定位存档，校验记录版本、关卡修订号与运行 ID。建议将现有雁迁徙槽映射至旧模式键，鲸用独立键；若评审采用迁移，需事务内执行且可重复，覆盖旧的「开始」「检查点」「已抵达」三类记录。
- [ ] 快照一次写入全队运动及救援、逐鲸深度／过渡／呼吸、能量、凝聚、补给、占用区域、分支、触发器和模拟 tick。船相位如果可由 tick 与配置重建，测试恢复时的姿态及接触结果。重试复用快照，按当前规则回满能量；其余模拟字段按快照恢复。输入归零、相机回该物种默认构图，继续后才推进 tick。
- [ ] 复用运行 ID 的事务内写入判断。覆盖同一标签页重复结算、双标签页旧运行写入、旧漫游档隔离、鲸／雁交替存取、损坏或不支持的修订号。失败后仍可从正确章节的最近有效检查点恢复，或重开当前航程。
