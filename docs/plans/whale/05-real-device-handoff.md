# 安静航道 · 真机试玩单

使用真实 iPhone Safari 与 iPad Safari 横屏各执行一轮。记录关卡 `whale-p2-8`、启动的构建、设备型号、iOS／iPadOS 与 Safari 版本、网络、屏幕方向和画质。把录屏或数据文件附到[执行记录](04-execution-record.md)对应编号。

## 启动

在同一局域网的 Mac 运行以下命令。在设备 Safari 打开终端显示的 Network 地址，横置设备，在生物选择页点「鲸」。新航程直接从海湾起游，有检查点时可继续或重新起游。首航用默认鲸模型。地址附加 `?whaleGraybox=1` 可对照灰盒，附加 `?diagnostics` 可用 Safari Web Inspector 读取状态与性能样本。

```sh
VITE_FEATHER_WHALE=1 npm run build
npm run preview -- --host 0.0.0.0
```

## WH-Q01 · 双手、船道、暂停

1. W0 设默认灵敏度。用左手持续推方向，右手先拖镜再按下潜。分别录下摇杆、转镜和能力输入同时出现的画面；右拖手指滑过下潜键时观察按钮状态。
2. 设置的「移动方向」里对比 A「随镜头转向」和 B「按住方向时锁定」。iPhone 先 A，iPad 先 B。每次起游用相同起点与操作顺序，比较松手到停稳的距离、镜头拖动时转向、复位后恢复航向的时间。记下误转、复位次数和疲劳。
3. W1 保持巡航，分别在默认视角和回望时观察预警。录下首次认出船的位置、受阻层、首次减速或下潜的 tick。按首次辨认时的位置和航向估算保持巡航至最早接触的时间，目标约 3 秒以上。先做水面等待，再从新航程做深潜过船。两个航程从相同初始相位起游，比较时记录抵达船前的实际 tick。另测低呼吸折返、过早上浮和领鲸已深潜但队尾仍浅潜。
4. 保持下潜时切到后台，再回 Safari。确认画面暂停，继续前深度和呼吸维持；显式继续后旧触点已释放。横屏转竖屏再转回时重复验证。最后停在 C1 静水，上浮并确认可以等待、换气与转镜。

## WH-Q02 · 首次玩家与整章

安排 3 位首次玩家各走一趟，只告知目标「让六只鲸在外海汇合」。逐人记录是否独立完成、总用时、首次认出船与渔网的时刻、实际选路与理由、是否折返接应和如何理解 6/6 前的等待。记录对呼吸、能量及静水区的理解、犹豫与误操作。用实际用时对照建议的 4–6 分钟。首轮目标是至少 2 位玩家能在 W3 解释两路的取舍，并在进入后主动选择出发时机、改变速度或停留。记录他们实际使用的线索，结合回放调参。

W0 首航记录玩家是否主动松手等到停稳、回望后能否找到复位、如何判断已经上浮并开始换气、是否留意队尾晚于领鲸上浮，以及出湾前是否需要场外提示。首航后用同一起点分别做完整练习与略过直游，再分别试按住和点按两种下潜设置。

W0 升级首轮让三位首次玩家在静音下从默认构图起游。目标为至少两位在 10 秒内发现一个想靠近的线索，并能说明水面出湾和浅潜借流的取舍。记录首次发现的线索、耗时、实际选线、犹豫位置、是否在亮水上浮等候，以及从哪里认出船舶方向。指定复测分别走水面与借流，均游到 C1。

首航之后再做指定复测。W2 先贴网缓转，再从宽线绕过。另从 C1 复现过早转向造成的真实擦网，记录掉队反馈、折返接应和超时重试。W3 先在噪声带前等一个安静空档通过，再试错过空档后在带后收拢队伍。走安静航道时沿礁脊转弯，再驶入静水湾浅潜、停稳、上浮。W4 在浅潜时带队入区，等全队上浮看到 6/6，并刷新确认保存的结果。

从有效 C2 单独复测 W4。一次沿亮水在水面入区，一次浅潜入区再上浮。领鲸刚越过入口时松开摇杆，按提示向亮水中央再游一段。留出空间后停稳并转镜，找到区外或正在上浮的同伴，核对 5/6 的原因与标记。记录默认视角第一次看到换气航标的位置、六鲸同框效果，以及汇合时切后台后继续演出和刷新结果的表现。

在 W2 从同一 C1 各走一次短口和宽线，记录船后何时看清两路、入网前怎么调整方向和速度，以及是否能在触网前通过队尾位置决定继续直游或缓行。W3 请三位首次玩家各试一遍，首轮目标是至少两位能在静音下看漂粒主动入流、感知轻推助力，并在礁间静水说出选择继续潜游或带队换气的理由。首轮结束后再对照水面宽线与两种借流走法。

## WH-Q03～Q04 · 素材、存档与性能

- 按相同路线对比灰盒和鲸模型。用默认视角、侧视、最低和最高俯角观察船体与网口；切换静音、减少动态、镜像、放大按钮以及低画质，再观察占用层、网口和接应方向。
- 在 Safari 验证 C1／C2 保存后刷新继续、失败后回档、资源加载失败后的重试和历史汇合。损坏档与旧版档复测使用隔离的 Safari 浏览会话，保留参与者现有航程。
- 同设备以相同画质、相同场景比较基线与升级构建。每种画质分别在 W1 观船、W2 网口和 W4 六鲸同框保持对应画面约 3 秒。Web Inspector 读取下面的表达式，记录帧时中位数、P95、Draw Calls、三角形和缓冲尺寸。记录从点击「鲸」到可操作的经过时间。内存仅在 Safari 可取得对应读数时填写。

```js
JSON.parse(document.querySelector("#game").dataset.performance ?? "null");
```

`segment`、`phase` 和 `tick` 对应样本场景。帧时使用真实 rAF 间隔，计数取当时渲染器，模拟保持 60 Hz。该读数包含开启诊断的采样成本。
