## WH-Q01 · 海湾与单船首轮

在真实 iPhone、iPad Safari 横屏各跑 W0／W1。沿同一条航线交换 A/B 试用顺序，保留默认灵敏度和相同船相位。先边游边回望，再边游边下潜；最后试松手缓行、上浮、复位和继续游动。记录误转、偏离、滑行距离、复位次数、恢复航向用时及疲劳。按住能力时切后台，显式继续后验证输入释放。用默认构图和回望视角分别辨认船的占用层与安全换气方向。

**首批验收。** 记录 WH-A01～A05 的自动化与真机证据。玩家用两手带 6 只鲸出湾，静音时也能理解何时等船或下潜，并到达船后换气水域。

## WH-Q02 · 灰盒首次通关

邀请首次玩家，先只说明目标「带全队在外海汇合」，首航后再安排指定路径。记录实际人数和使用设备。首航观察玩家何时辨认危险、是否理解呼吸与能量、为什么选路、如何发现并接回同伴、如何理解等待 6/6。首航后补做 W1 两种解法、W2 接应失败重试与 W3 换路；记录观看危险到操作的时间，以及每段操作密度和休整感。

**整章验收。** WH-A06～A11 记录两条旅程回放及两类失败重试。记录 3 位首次玩家的独立航程，实测用时对照 4–6 分钟目标，保留典型问题和复测路径。

## WH-Q03 · 水彩、配乐与可访问性回归

先试接 W0／W1 的鲸 GLB、表层水纹和下潜层色彩，并以《Deep Blue Drones》试验起游、穿越和安全水域的音量过渡。记录 GLB 来源、轴向、海面比例、动画和授权；只装配该段所需的资源。扩到全章前用同版灰盒回放对照默认、侧视、最低／最高俯角的水面、船与网。低画质减少氛围开销，按原碰撞数据绘制关键轮廓。复测静音、减弱动态、镜像、按钮放大与失焦恢复。

## WH-Q04 · 生产构建、性能与证据

- [ ] 实现后执行 `npm run check` 和 `npm run test:e2e`。从生产构建验证雁线入口与资源；用已明确启用原型入口的预览构建验收鲸线。将鲸专项纳入 Chromium、桌面 WebKit 和横屏 WebKit 的适用项目，确认桌面 WebKit 的用例过滤器实际匹配鲸用例。
- [ ] 记录目标真机型号、系统／Safari 版本、构建、网络、画质和测试路线。比较 W1 船道、W2 网口和 W4 六鲸同框的帧时、Draw Calls、三角面、首次可操作时间及可取得的内存数据。以 60 FPS 为优化方向，是否降档至 30 FPS 以实机为准。模拟始终按 60 Hz。
- [ ] 桌面与真机验证正常、旧版、损坏存档和资源出错后的恢复入口。报告观测到的结果，仿真和真实设备证据分别记录；未验证项附影响及复测入口。

每次提交记录任务与结果、负责人、构建／关卡／配置版本、运行命令、实际路线与模式、设备或仿真环境、截图／回放链接，以及未通过或待测项。失败或尚无证据的项按对应编号复测。
