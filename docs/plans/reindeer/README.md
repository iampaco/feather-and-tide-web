# 《羽与潮》驯鹿章节开发计划 · 苔原过路

**当前体验修订为 `reindeer-p3-3`。** 围栏短弯、公路过洞人数、矿区背风地引导和冬林至苔原的休整空间见 [带队体验与验证](experience-upgrade.md#驯鹿带队体验-reindeer-p3-3)。下文 RD-01～RD-10 保留初版开发历史。

**阶段 P3 · R0–R4 可玩预览。** 带领 1 只领鹿和 8 名同伴，从冬林经过公路、围栏与矿业廊道边缘，到春季苔原落脚。整章采用一张连续地图、旅程模式、两个检查点。首次通关目标约 4–6 分钟，记录主动观景和暂停用时，供试玩调参。

玩法以 [GDD v2.0 §3–5、§6.4、§7、§11](../../../Feather_Tide_Gameplay_Design_v2.0.md) 为准，架构采用 [TDD v1.0 §3–6、§8.2、§11–12](../../../Feather_Tide_Threejs_TDD_v1.0.md)。[ADR-010](../../adr/010-journey-only-entry.md) 确定标题、生物选择和仅旅程流程，[ADR-009](../../adr/009-dual-hand-camera-controls.md) 提供待实机比较的 A/B 镜头映射。旧版《游戏玩法方案：操作与关卡挑战》v1.1 §5.4、§9、T21/T22 作为公路、围栏和等候的设计参考。涉及正式开放、十年解锁或接班的产品决策，按本文「发布与后续决策」处理。

## 1. 从哪里开始

选择依赖已满足的第一项任务，先读对应代码、数据和测试，再实现该项最小可玩范围。每次接手先复核下表状态和文末的执行记录。任务内部可分批合入，按实际证据勾选，设备待测和外部决策单独记录，继续推进独立任务。

## 2. 路线与玩家决策

| 段落            | 玩家要做的事                                           | 布局和反馈                                                                                                   | 出口                                                         |
| --------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| **R0 冬林出发** | 左手转向和调速，松杆停步，回望队尾，按住等候再出发     | 安全林地容许队伍自然拉长。用短提示引导观察和复位，蹄印标出行进方向，队尾可见地走近                           | 全队可沿林间小路到近侧路肩                                   |
| **R1 公路**     | 在路肩收拢队伍，观察车灯方向和车流，沿路找到涵洞       | 两侧有安全等候点。远端车灯、道路描边、踏迹和动物通道路标在默认视角可读。直接横穿只省少量路程，经涵洞稳妥通过 | 全队到远侧安全区后记录 **C1**                                |
| **R2 围栏**     | 比较缺口，遇到队尾没通过时决定等候、折返或带队改走宽口 | 首轮一个宽口、一个窄口。围栏轮廓、实际净宽和被踩出的小径给出同一条信息。完整布局再评估旧案的第二个窄口       | 全队可过宽口并重新集齐。领鹿独自越过围栏时保留队尾指示和回程 |
| **R3 矿业廊道** | 试走近而易松散的尘雾边缘，或绕经恢复植被带补给         | 尘雾压低环境能见度并影响凝聚。外侧有可读的补给路线和安全等候空间，尘雾内仍保留边界、路标与救援提示           | 两条候选路线接回安全地带，全队到齐后记录 **C2**              |
| **R4 春季苔原** | 回看队伍，减速腾出空间，让最后一只鹿进入目标区         | 进入终点后显示实际到达数。等候时玩家仍能移动、回头接应。满足 9/9 后全队卧下，镜头舒展，主题曲尾奏收束        | 同一次旅程只生成一次结算                                     |

地图沿前进方向依次连接「冬林 → 近侧路肩／涵洞 → 远侧安全区 C1 → 围栏 → 植被恢复带／尘雾边缘 → C2 → 苔原」。每个受阻位置在灰盒上标出回程、可停步位置和备用通路。尺寸由停步距离、九只鹿的队列长度和真实净宽反推。

## 3. 工程契约

| 责任域               | 实施边界                                                                                                                                                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **模拟与队伍**       | 在物种判别联合中接入 `reindeer` 和专属配置。用稳定 ID 的 `actors` 表示完整队伍，出生与读档校验 1+8。保持 `following → loose → strayed → rejoining → following`。60 Hz 固定 tick 推进移动、等候、救援、能量、车流和阶段事件。模拟依赖纯 TS 数据与几何。                               |
| **输入、等候与镜头** | 沿用 `WorldInput.move` 世界 XZ 向量和 `ability`，驯鹿解释为「等候」。按键接管规则与镜头指令沿用现有输入边界。按住和点按切换进入同一套模拟。摇杆＋拖镜和摇杆＋能力分别可并行，等候生效时摇杆只转向。相机使用只读快照。                                                                |
| **地面、围栏与公路** | 关卡数据声明通行面、坡度边界、道路、涵洞、围栏、开口、车辆周期和预警。领鹿与每个同伴用同源 XZ 轮廓和自身碰撞半径扫掠。涵洞与路面若 XZ 重叠，明确通行层及入口切换边界，并独立校验两层的绘制、碰撞和等候许可。车体与逐鹿碰撞按同一 tick 区间采样。                                     |
| **失败、到达与保存** | 旅程失败有两种情形。能量归零且领鹿在安全栖息地和补给点以外，或任一同伴救援超时。接触车辆的反馈是受惊、能量／凝聚代价和可救援离队。检查点、HUD 和落脚共用角色名单和适用的到达谓词。8/9 保持游玩，9/9 就绪才进入落脚并冻结失败判定。存档按物种、关卡、模式隔离，保留旧雁槽的兼容路径。 |
| **表现与反馈**       | Renderer、HUD、动画和音乐消费同一快照及事件。地形高度和动画可插值，接触与可通行性由模拟决定。路面、围栏、缺口和预警共用关卡数据。低画质可简化氛围，关键轮廓与提示的可读性逐项验收。                                                                                                  |

优先复用 [固定时钟](../../../src/core/clock.ts)、[GameRuntime](../../../src/core/runtime.ts)、[输入管理](../../../src/input/input.ts)、[CameraDirector](../../../src/rendering/camera.ts)、[二维几何](../../../src/levels/geometry.ts) 和 [存档](../../../src/core/save.ts)。检查 `world.ts`、`goalStatus`、`readCheckpoint`、Schema／加载器和菜单中现有的雁／鲸二选一分支，逐个接入第三种物种。若车体确实复用鲸船的平移采样和相对扫掠，提取共用计算并复跑鲸船回放。接入第三物种时只收敛当前确有重复的逻辑。[移动危险几何参考](../../../src/levels/whale-geometry.ts) · [共享到达规则](../../../src/simulation/world-rules.ts)

### 原型参数与验证方法

| 参数                 | 初始做法                                                                | 如何确认                                                                                         |
| -------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 停步、转向、跟随间距 | 松杆数步停稳。走／巡航／跑、减速、转向和跟随使用物种配置                | 记录停步距离、窄弯偏离和整队通过用时。用巡航停车距离布置 R1 路肩                                 |
| 等候                 | 约 2–4 秒、约 3 倍队形半径。触发后进入受控停步，停稳后摇杆只改变朝向    | 比较能否看出队尾开始靠拢、是否知道何时可以出发、按住是否疲劳。观察安全区外微量消耗是否制造催促感 |
| 低能量、救援         | 约 30% 提示补给方向、约 15% 限制加速。救援约 40 秒、接应约 2 秒作为初值 | 以可重放低能量初态走完补给路线。验证正常接应、绕回到同一可通行面、太远、暂停和超时               |
| 镜头映射             | A 随当前镜头基准限速转向。B 左手按下时固定本次移动基准                  | 在同一路肩和缺口交换 A/B 顺序，记录误转、路线偏离、复位、恢复用时和两手疲劳，试玩后确定          |
| 车流预警             | 巡航接近时约 3 秒反应窗口，考虑停步距离与观察负担                       | 在默认镜头与回望构图记录首次可辨信号、开始制动、预警区边界和接触 tick，用首次玩家录像复核        |

## 4. 开发任务清单

### RD-01 · 工作区基线、俯视草图和契约

**依赖无。** 检查 [AGENTS.md](../../../AGENTS.md)、现有规则、测试与资产。先做一份俯视灰盒草图和两份关卡数据样例，再确定共享接口需要的最小变化。

- [x] 登记当前构建入口、测试结果和与任务无关的工作区改动。已有公共提交时按仓库规则使用独立分支和 worktree。若仍无首个提交，在获授权的现有工作区串行推进，保留其他人的内容。
- [x] 画出 R0–R4、C1/C2、安全路肩、备用通路、补给和接应地点。准备 R1 单车／涵洞与 R2 宽窄口的关卡样例，标出高度与通行层约定。
- [x] 确认物种状态、关卡数据、能力输入与存档的接口及调用方。收集旧雁与鲸存档和固定输入回放作回归基线。验收时记录实际样例、基线命令与结果。

### RD-02 · 驯鹿状态、地面移动和跟随

**依赖 RD-01。** 修改候选范围为 `src/core/game.ts`、`runtime.ts`、`src/simulation/world.ts` 和驯鹿专属模拟模块。

- [x] 加入物种判别、配置、九只鹿的出生及稳定 ID。处理普通走／跑、限速转向、松杆制动和停住后的方向响应。移动向量经现有适配器进入模拟。
- [x] 同伴按实际地面路线步行跟随。使用有界的跟随速度和局部通行引导验证拐弯、急停、坡度和同伴间距。领鹿位移始终由玩家有效输入与地面约束决定。
- [x] 提供平地、弯道和窄口模拟夹具，覆盖停止距离、换向、逐鹿碰撞、状态变化及 30／60／120 FPS 下固定输入的结果一致性。关联 RD-A01、RD-A02、RD-A07。

### RD-03 · R0 等候、双手输入与灰盒入口

**依赖 RD-02 的状态及移动接口。** 修改候选范围为 `src/app/main.ts`、`index.html`、现有输入和相机接线、驯鹿 HUD／场景模块、驯鹿关卡数据。

- [x] 配置显式驯鹿预览开关，建议 `VITE_FEATHER_REINDEER=1`。启用时从现有卡片进入 R0 引导，采用异步场景及资源加载。关闭时卡片正确显示「尚未开放」。菜单提示、按钮可访问名称、暂停、重试和结果文字均使用驯鹿语境。
- [x] 实现 T21。按住等候时领鹿受控制动并停稳，维持转向而无推进。松开等候后，摇杆中立时持续站立，摇杆有输入时按地面移动规则起步。范围内、可沿地面接近的同伴逐步靠拢，范围外或被阻隔的同伴留在真实位置。重复短按效果按实际进度计算。
- [x] 实现输入并行、镜像、放大和点按切换。暂停、切后台、失焦、指针取消及转回横屏后按现有流程释放输入。R0 提供可略过的移动、松手、召集、回望、镜头复位教学。关联 RD-A03、RD-A04、RD-A13。

### RD-04 · R1 车流、涵洞与车道禁用

**依赖 RD-02、RD-03。** 修改候选范围为 `src/levels/schema.ts`、`src/levels/load.ts`、二维几何、驯鹿模拟与场景、`public/levels/`、`tools/validate-levels.ts`。

- [x] 关卡载入时校验稳定 ID、危险与预警关联、轮廓、宽度、通行层、车流周期、合法出生位置及检查点引用。保留既有雁／鲸 JSON 验证。由固定 tick 和配置导出车辆姿态，视觉车体与每只鹿的判定使用同源轮廓及相位。
- [x] 实现 T22。车道上的能力进入禁用状态，按钮变灰并提示「先离开车道」，领鹿仍遵循摇杆输入。站立时保持在当前位置。支持震动的设备可补充轻震。验证按住和点按在车道进入、驶离及跨层边界时的行为。建议离开车道后重新触发才可召集，按试玩结果记录决议。
- [x] 在近、远两侧做安全等候点，明确涵洞入口和出口。涵洞通过与车道接触使用同源判定，覆盖同 XZ 处的两层、路肩边界、相向快速移动和同伴分别跨入车道。以回放验证安全路线和误入后可接应路线。
- [x] 保留默认镜头和回望视角的来车方向、通道入口及安全停步位置。实测巡航反应窗口。关联 RD-A05、RD-A06、RD-A12。

### RD-05 · C1 与物种存档接入

**依赖 RD-02、RD-03。C1 端到端验收依赖 RD-04。** 修改候选范围为 `src/core/save.ts`、`src/core/runtime.ts`、驯鹿关卡、选章／继续流程与集成测试。

- [x] 领鹿和同伴全部进入安全检查点且无离队或正在归队成员时保存。全量快照含成员位置、方向、速度、队伍／救援、等候进度、能量、凝聚、补给余量、区域、路线选择、已触发事件及 tick。车辆相位可由关卡修订号和 tick 重建，回放核对原状态与重试的车辆位置。
- [x] 从标题验证继续、重新出发、刷新、无效／不兼容记录及恢复。失败重试按现行规则回满能量，其余权威模拟字段从快照恢复。镜头回默认，输入为中立，再由玩家继续操作。
- [x] 验证旧雁旅程槽、鲸槽、鹿槽并存，旧漫游档隔离，跨标签旧运行写入受已有事务保护。保存失败有可理解的恢复入口。关联 RD-A06、RD-A10、RD-A13。

### RD-06 · R2 围栏、宽窄缺口和主动接应

**依赖 M1。** 先交独立宽窄口夹具，再把路线接到 C1 之后。

- [x] 从同一份围栏几何生成可见段和通行约束。用稳定队列的转弯、挤靠和追赶验证宽口可让全员通过，窄口能自然使队尾滞后。记录实际宽度、转角和测试输入。
- [x] 在滞后发生时提供方向与人数提示。越过跟随距离或发生接触后，同伴在有明确回程的地点等待接应，使用既有救援状态和计时。覆盖从对侧发出召集、折返回到同一可通行面、完成接应和超时。
- [x] 交付 C1 出发经宽口的回放，以及试走窄口、折返、接回或重新集齐再走宽口的回放。默认镜头和静音条件均可辨认两口。关联 RD-A07、RD-A08、RD-A12。

### RD-07 · R3 资源取舍、R4 落脚和整章串联

**依赖 RD-05、RD-06。** 把矿业边缘、恢复植被带、C2 和苔原接成连续关卡，复用共同的旅程规则。

- [x] 短路与外侧恢复带在分岔前可比较。配置干扰、可达补给和低风险空间，校验补给容量、低能量提示和早停等候。记录路线实际进入点，C1 重试可重选，保存 C2 后保留已完成的选择与触发状态。
- [x] C2 使用已验收的全队检查点资格和存档接口。8/9 时显示「等待同伴」，区内离队或归队中的角色仍挡住落脚。9/9 就绪才冻结模拟并开始卧下演出，短演出支持跳过。
- [x] 交付从正常入口到 9/9 的整章主线回放，覆盖 C1/C2。为 R3 两条候选路线分别留可完成的回放。补充 8/9、最后一位入场、落脚同 tick 的失败判定顺序和重复结算夹具。关联 RD-A09～A11。

### RD-08 · 失败重试与雁／鲸回归

**依赖 RD-05、RD-07。** 将驯鹿纳入共享规则、存档和测试入口。

- [x] 分别触发安全区外能量耗尽和救援超时，从 C1／C2 重试并回放到落脚。检查队尾、救援、区占用、补给、触发记录及车辆相位。核对安全区停留和暂停／后台的计时边界。

## 7. 发布与后续决策

- **预览交付。** M3 以开启驯鹿预览的构建交付可独立游玩的 R0–R4。正式开放入口和解锁方式由项目负责人确认后更新相关 ADR 与 T23 测试。GDD §12.3 的鲸十年解锁条目保留为正式开放决策的设计依据。
- **章节收束。** R4 落脚和尾奏属于本章。多年份传统与接班演出作为独立 P3 后续工作包，待确认其与长期进度的关系后拟任务，沿 GDD §12 和 §17 记录。
- **试玩决策。** 在执行记录写下 A/B 默认映射、等候耗能、离开车道后能力恢复方式、R2 缺口数量、R3 路线调参及实际章长。对 GDD／TDD 的玩法、参数或接口变更同步补充影响说明，需要项目负责人确认的规则改动走 ADR。
