# 苔原过路 · 真机与首次试玩单

验收目标为真实 iPhone 和 iPad Safari 横屏。两台设备分别跑驯鹿旅程，按 [RD-10](README.md#rd-10--预览设备验收与交付) 回填结果。浏览器自动化结果可用来对照交互与路线。[执行记录](execution.md)

## 开始试玩

Mac 和测试设备接入同一局域网。运行以下命令，在设备的 Safari 打开终端显示的 Network 地址。横屏进入「进入游戏 → 驯鹿 · 体验原型旅程」。使用同一个构建测试两台设备。

```sh
reindeer_build_dir="$(mktemp -d "${TMPDIR:-/tmp}/feather-reindeer-device.XXXXXX")"
VITE_FEATHER_REINDEER=1 npm run build -- --outDir "$reindeer_build_dir"
npm run preview -- --outDir "$reindeer_build_dir" --host 0.0.0.0 --port 4399 --strictPort
```

### 首次玩家

开新旅程，只告诉玩家「带全队到苔原」。开始计时后观察路肩、涵洞、宽口和队尾分别何时被发现，玩家有无主动等待、为何选择该路线。首次出现 8/9 时，记录玩家从数量提示到采取行动的过程。记录总用时和需要场外提示的具体时刻，按实际情况填入下方表格。观察结束后再用相同片段复测最影响通关的问题。

### 输入、镜头与恢复

1. R0 巡航和奔跑时各按等候一次。确认领鹿先沿原方向停步，再响应原地转向。记录最后一步到抬头呼唤、队尾靠拢与应答的感受，静音重复一次。测试从拖镜区滑到能力键和从能力键滑入拖镜区，确认松开后位置稳定。
2. iPhone 从 A 映射起步，iPad 从 B 起步，再用同一路段交换对照。记录偏离、误转、复位次数、恢复用时和两手疲劳。
3. 按住等候时暂停或切到后台，返回后确认显式继续、输入已释放、tick 在中断期间冻结。转竖屏再转回横屏，检查同一行为。开启镜像、大按钮、点按等候和减弱动态，再验证按键和方向提示。
4. R1 在默认、侧视和回望时记录首次看见道路、车流方向和涵洞的时刻。确认路肩能等候、车道提示「先离开车道」，从涵洞可安全过路。通过 C1 后刷新验证继续。
5. R2 留意队尾在路上、被围栏隔开、待接应及归队提示与实际位置是否一致。R4 逐步进入落脚区，记录 8/9 时能否找到目标同伴，随后完成 9/9。

### 首帧、帧时与渲染取样

另开一次 R0 新旅程，网址附加 `?diagnostics`。准备冷加载样本时，可用新私密标签页保持测试与原旅程独立。记录首次加载，再在同一设备分别用标准和低画质采样 R1 单车、R2 围栏及 R4 九只同框。相同画质用同一位置和观察角度。每个场景保持前台数秒，收集稳定的帧时窗口。

在 Safari Web Inspector 读取以下内容，按设备和场景保存。每次场景切换后的新窗口会更新 `frames`。截图可一并保留。

```js
JSON.stringify(
  {
    startup: JSON.parse(
      document.querySelector("#game")?.dataset.reindeerStartup ?? "null",
    ),
    frames: JSON.parse(
      document.querySelector("#game")?.dataset.performance ?? "null",
    ),
    state: JSON.parse(
      document.querySelector("#game")?.dataset.flight ?? "null",
    ),
  },
  null,
  2,
);
```

- `titleReadyMs` 从导航开始计算到标题入口开放。新旅程的 `from: "selection"` 为点选驯鹿到首个可操作帧，由前台 rAF 提交绘制时记录。若先出现存档选择，`from: "start"` 从玩家确认继续或重开计时，附检查点编号。
- `medianMs` 与 `p95Ms` 取渲染帧间隔。`calls`、`triangles`、`geometries`、`textures` 为 Three.js 当时报告的计数。最后两项是渲染器资源数量。若 Safari 提供进程或时间线内存读数，另外注明来源、单位及采样时刻。
- 设备帧率随画质、场景和电量等因素变化。将标准档与低档分开对照，保留实际数值及掉帧时的操作。诊断数据由浏览器本地提供。

## `reindeer-p3-2` 新增首次玩家检查（待真人／真机）

1. R0 能否从实际靠拢人数判断何时出发？按满呼唤但同伴受阻时，提示是否可理解？
2. R2 是否理解窄口不能让全队通过？S 弯是否自然引发收速、停步或回望？从后两排接应时，宽口提示是否指对位置？
3. R3 能否区分平静／预告／活跃并注意中间背风地？玩家是否知道能折返换路？记录一次冒进后的恢复行为，不安排必然离队。
4. 从相同分岔体力比较两路选择原因。记录主动等候、补给停留和观景用时，不以按键次数衡量成功。
5. 至少 5 名首次玩家，目标 4 人无需场外操作提示完成；目标 4–6 分钟，暂停及主动观景另计。当前没有这些真人数据。

## P3-3 带队试玩

1. 在 R1 到对岸后分别试普通停步、按等候和缓行前进。记录远侧人数和队尾是否能指引玩家选择。
2. 在 R2 先从同一起点观察两个全员通道。各走一次短弯和宽路，记录过栏人数、入弯时机、主动回望和折返回位。若队尾卡在围栏，分别在正对缺口和隔着围栏的位置呼唤。
3. 在 R3 比较尘雾平静与活跃时的出发决定。记录玩家能否从下一处安全地和入区人数判断该前进、收队或折返。
4. 在 R4 停在融雪坡回望并静音重试，确认随时可以继续到 9/9 落脚。
