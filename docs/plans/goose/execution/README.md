# 《羽与潮》斑头雁章节详细执行计划

**目标**是在桌面、iPhone 和 iPad 上交付一趟顺手、可读、值得停留的水彩迁徙旅程。玩家能独立带着 12 只雁起飞、在岔路作选择、接回同伴、提前看懂风机外围，并在最后一只雁抵达后一起落脚。P0 先完成 S0–S6 的完整体验，P1 再完成十年迁徙和领队交接。

## 从当前代码开工

Web 仓库从 WebGL 2 测试场景、构建和烟测起步。现有交付与各任务验证状态见 [执行记录](record.md)。前序 [阶段计划](../README.md) 记录设计依据和范围。`Assets/` 已有雁模型、动画和关卡装配样本，优先用小范围导入试验确认可复用的部分。

1. **第一批**按 `E02` 固定时钟、`E03` 数据入口、`I01` 双手契约与 ADR-009 提案推进。先对齐共享接口，再接一个可用触屏操作的单雁场景。记录第一批次版本，方便后续回放和比对。
2. **第一段可玩闭环**先做到 12 雁飞行、结阵、可预告的接应和全员落脚。S3 和 S4 的可读性原型能提前暴露关卡空间问题，完整路线仍按小地图规则验收后接入。
3. **首个音画样段**在 S0 同时验证雁动画、湿地构图、第一次音频解锁和初学者输入。先取一组游戏镜头截图和一段实机录像，再把同一素材标准用于其余段落。
4. **体验迭代**一轮只改变需要验证的因素，例如同一航线对比镜头映射，或者在同一构图调整风机边界。保留修订前后的回放与数据，读图或手感问题修复后复测再标记通过。

## 执行记录

每张任务卡的编号可用于分支、PR、测试或试玩记录。认领时填实际负责人、所用关卡和构建版本。变更跨 `GameState`、`LevelSchema`、资源清单或存档时，在实现前约定接口与迁移方式。任务完成时链接测试日志、回放和相应设备证据，沿用 [T01–T23 与 V2-01–V2-18 矩阵](../05-verification-and-release.md)。

记录可沿用以下字段。

```text
任务 / 状态 / 负责人 / 依赖
提交或构建标识 / levelRevision / 配置版本
交付文件 / 自动化命令与结果 / 回放或截图 / 机型与系统
通过的验收编号 / 待验证项及影响 / 下一次复测步骤
```

本计划的试玩样本、模型取舍和技术细节都是实施建议。涉及产品规则的决定仍依据试玩与负责人确认更新设计记录。镜头映射、结阵数值与第二检查点等候选项见 [待决问题](../07-decisions-and-backlog.md)。
