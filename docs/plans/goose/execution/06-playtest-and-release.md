# 06 · 试玩、调参与发布

体验验收贯穿 M1、M3、M4–M5。记录玩家实际做了什么、哪里停顿、怎么恢复、看见什么。玩法与公平性用 [T01–T23 和 V2-01–V2-18](../05-verification-and-release.md) 检查，手感、节奏和情绪用以下三轮验证。

## Q01 · 第一轮，双手试飞

1. 在真实 iPhone 和 iPad 横屏用同一条安全路线试玩。让玩家巡航并看左/右地标、回望队尾、复位，再用两手通过结阵直线与解除后的宽弯。
2. A/B 对换次序，从相同起点与配置开始。记录误转、偏离、复位次数、恢复航向用时、滑出手指区和疲劳反馈。用一轮连续移动加视角和一轮连续移动加能力测试双手并行。
3. 加做镜像、大按钮、点按能力及中途切后台。记录屏幕遮挡和实际指针状态。选择映射时说明它解决的问题和留下的取舍，复测引入的行为变化，再更新 ADR-009。

## Q02 · 第二轮，灰盒首次通关

建议在当前构建邀请 5–8 位首次玩家作为迭代样本，实际人数和机型写入记录。开场只说明玩法目标“带全队抵达”。先看玩家自行发现的做法，完成一轮后再做针对性任务。体验目标以可重复发现与复测为准，样本规模属于计划建议。

| 任务             | 观察与量测                                                       | 看到问题后的优先调整                                          |
| ---------------- | ---------------------------------------------------------------- | ------------------------------------------------------------- |
| S0/S1 起飞并转弯 | 是否会松手、用两手转镜、为何结阵或解除，误触和找按钮次数         | 先调初始镜头、触区响应、速度曲线或提示出现时机                |
| S2 选路          | 在承诺选路前能否指出两条入口并说出一项取舍，记录实际选路与犹豫点 | 先调整 A 的构图、地标、风痕和两条路的发散角度                 |
| S3 救援          | 发现、折返、接近、接应各耗时，失败是否理解原因，剩余多少秒       | 优先修风向预告、目标定位、折返空间与接应反馈，再校准时限      |
| S4 风场          | 在默认和回望角度是否看懂边界与外围，记录首次看见预警到接触秒数   | 优先修同源轮廓、遮挡和预警位置，再调场景风压与颜色            |
| S5/S6 返航落脚   | 能否找到补给、解释为何等待；记录从 A 重试用时与愿不愿再试        | 优先修补给可达性、落脚镜头与信息反馈。结合实际重试评估 B 候选 |

**体验目标**是多数首次玩家能独立完成旅程、解释两路差异并看懂为何要救援和等队。在计划样本为五人时，可把至少四人做到作为本轮改进参考，记录原始人数和具体问题。收集希望在哪停留、哪一段太空或太急、是否愿意换路。只有实际观察支持后，才确定章长、镜头参数和相关数值。

## Q03 · 第三轮，素材版回归与舒适度

- [ ] 使用同一 `levelRevision` 的灰盒路径对照素材版，覆盖旅程山口、旅程长湖、漫游山口、漫游长湖。跑两种旅程失败再重试，确认没有因模型、音频或加载变化导致计时/相位重复推进。
- [ ] 实机录制正常模式的全段体验，另覆盖默认镜头、静音、减弱动态、镜像与放大、降画质组合。记录默认跟随视角下的风险窗口、回望时抢占的提示、配乐能否留下舒展空间。
- [ ] 遇到明显可玩性问题时固定复现路径和配置。先改能解释现象的一项，重跑同场景并找新试玩者复核关键问题。记录两条路线是否值得重玩、是否感到在照顾同伴及高潮后的释然。

## Q04 · 性能、兼容与候选构建

1. **测试条件。** 记录设备、iOS/iPadOS/Safari 版本、场景、构建版本、网络、画质、冷启动或热机。回放固定巡航、S2 近景、S4 风场、S6 十二雁落脚和快速重试，另做完整实机通关。
2. **计量。** 记录首屏字节、启动到可控时间、帧时间分布或平均/低帧、卡顿场景、Draw Calls、三角面和可取得的内存数据，比较低档与标准档。以目标机 60 FPS 为优化方向，低端按 30 FPS 降档实测。模拟仍固定 60 Hz。记录无法测的指标及原因。
3. **恢复。** 复测路径含页面隐藏、重回前台、屏幕旋转、WebGL 中断、弱网资源失败、正常/损坏/旧版存档，确认各有明确恢复入口。证据要包含前后输入、帧、音频或快照相位。
4. **构建。** `npm ci`、`npm run check`、接入后的数据/资产校验及 `npm run test:e2e`。使用 `npm run preview` 从生产构建验证页面入口和实际资源路径，记录 GitHub Actions 运行及版本标记。目标 Safari 的合格证据来自对应实机。

## 发布判定

- 阻塞问题包括输入粘滞、默认视角危险不可读、掉队不可救、重试改变相位或丢失队员、11/12 结算、可达补给缺失与正式入口无法恢复等。修复后用原始场景和设备复测。
- 完整记录玩家能自由选路、救援合理、静音及低画质能玩、音画舒展、全队落脚和设备可接受的实时性能。未验证记明原因、影响与复测动作。候选版按实际证据确认可发布状态，再进入后续十年内容。
