# 04 · Three.js 建模与 Blender 资产接入

**目标**是在保留水彩风格和清晰轮廓的前提下，按对象选最合适的做法。水面、过渡地形、风、危险区及规则标记用 Three.js 随配置生成。雁的骨骼与动画、风机造型和有辨识度的地景优先试用现成 Blender GLB。现成包通过轴向、画面、通路和性能验证后，可整段采用或拆取网格与材质。

## 已核对的资产起点

- `CHR-001` 雁骨架和 `ANM-001` 巡航振翅的素材清单标为 `done`，可以先验证 Web 共享骨架。`ANM-002` 至 `ANM-009` 及 `CHR-002` LOD 待审。`CHR-001` 的 GLB 无剪辑，`ANM-001` 含 `Cruise_Flap_Loop`，`ANM-003` 含 `Glide_Loop` 和 `Circle_Loop`，`ANM-007` 有浅水和泥滩落脚剪辑。[雁骨架](../../../../Assets/Watercolor/Goose/Blender/CHR-001/v001/README.md) · [巡航振翅](../../../../Assets/Watercolor/Goose/Blender/ANM-001/v001/README.md)
- `LVL-S0` 至 `LVL-S6` 有组装 GLB、布局 JSON 和 QA，均标为 `needs_review`。七个主 GLB 合计约 **69.1 MiB**（目录内现有源导出体积）。若按实际首屏测量需要减载，先测拆分、提取地标和共享贴图的收益。部分素材用旧版固定后上方机位审阅，新双手镜头要重新评估遮挡、通路和边界。[S2 岔路](../../../../Assets/Watercolor/Goose/Blender/LVL-S2/v001/README.md) · [S4 风场](../../../../Assets/Watercolor/Goose/Blender/LVL-S4/v001/README.md)

## 任务卡

### R00 · 两项早期接入试验

- [ ] **A 雁。** 用本地开发样段加载 `CHR-001` 和 `ANM-001`。核对骨骼命名、枢轴、贴图和 +Z 世界前向。在模块根部显式处理 Blender 导出朝向。做一只到 12 只的对照，确认骨骼独立又能共享几何与材质，记录 Draw Calls、顶点和帧时间。
- [ ] **B 湿地。** 同一 S0 构图分别以纯 Three.js 水面/岸线配景和 Blender 关键模块试渲染，再组合成候选。比较地标轮廓、横屏裁切、结队可见性、加载和帧时间。记录候选资源 ID、结论及需要回 Blender 调整的部分。

### R01 · 角色整合与剪辑

- [ ] 核对滑翔、盘旋、转向、成阵、呼应、浅水/泥滩落脚等源剪辑，通过审核的部分合为共享雁资源或单独的剪辑数据。各动画源 GLB 均带一份蒙皮和四张图像，先检查轨道绑定与纹理去重，避免为每段动作加载整套角色。
- [ ] 在表现层按速度、转向、形成度与离队状态选择和混合剪辑。实体根位置只来自快照，本地动画保留姿态。覆盖初始加载、恢复插值、切换剪辑、热重试后的骨骼状态。
- [ ] 小屏辨认领队与同伴，静止、巡航、松手、成 V 形和低角度近水飞行均可辨。达到实机瓶颈时测候选 LOD、阴影简化与材质共享的实际取舍。

### R03 / R04 · 构图、水彩与可读性

- [ ] 用统一色温、纸纹尺度、柔和光照和分层远景，制作 S0 晨光、S3 侧风、S4 风场和 S6 暖色四张实际游戏机位参考。优先看地标、边界和队形，再增加雾、水彩边缘和粒子。
- [ ] 优先用 Three.js 的 `BufferGeometry`、材质与实例化构建共用地形片段、岸线、阴影与重复植物。程序布局依据关卡坐标，视觉扰动与权威模拟隔离。风压效果根据风与 Rotor 相位渲染，逻辑碰撞与可见轮廓读取同一几何。
- [ ] 记录默认、轮廓边界、回望、减弱动态和低档的对照截图，从小屏裁切检查清晰度。所有影响通行的几何以关卡数据验证，资产修改后复跑相应路线。

### R05 · 版本、加载与性能

重新生成 Web 雁模型和剪辑用 `python3 tools/pack-goose-animations.py`，本次使用 Pillow 12.2.0。转换保留 Blender 源 GLB，已生成的 Web 资产可直接参与 `npm run build`。`npm run validate:assets` 核对两端哈希、512 × 512 PNG 贴图及未改变的非贴图缓冲。

- [ ] 每项运行资产登记 `assetId`、源文件和版本、许可依据、导出路径、尺寸、轴向/枢轴、纹理、剪辑及适用段落。复用、重导出或 Three.js 生成的选择记到对应任务。原始 `.blend`、审阅视频和候选包留在 `Assets/`，批准的运行资产放 `public/assets/`。
- [ ] 按实际测量将资源分为起飞必需和后续分区。避免在岔路选完才开始加载可见地标，提前准备下一处可见资产，并复用仍在视野中的共享资源。弱网测能否看到正确边界、读取补给并从明确的加载失败提示返回或重试。
- [ ] 比较首屏字节、首次交互、解码/上传停顿、场景 Draw Calls、峰值内存与重试后的资源回收。以实测瓶颈决定压缩、拆包与实例化的优先级，保持渲染档位与规则独立。高画质可强化水彩层次，低档保留危险、出口与队伍。

**验收证据**包括可复用模型与生成模型的名单、源文件追溯、可运行的 Web 导出、默认/转镜截图、关键关卡回放与实际移动设备的对照结果。参考 [素材库约定](../../../../Assets/docs/素材库使用约定.md)及 [TDD §9–11](../../../../Feather_Tide_Threejs_TDD_v1.0.md)。
