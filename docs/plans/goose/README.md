# 《羽与潮》斑头雁章节开发计划

本计划从当前 Web 工程出发，先交付第一条可完整通关的斑头雁路线，再扩展斑头雁十年迁徙线。阶段编号沿用 TDD 的 M0–M5，P1 对应 GDD 的十年进度与后续雁关卡。阶段入口由交付物和验收证据决定，工期与人员分配在首批任务拆分后估算。

开发时使用 [详细执行计划](execution/README.md)。其中包含逐项可认领的任务卡、[每段的场景制作单](execution/03-s0-s6-production.md)、[Three.js 建模与 Blender 资产接入方案](execution/04-modeling-and-assets.md)和[试玩调优脚本](execution/06-playtest-and-release.md)。

## 两个交付边界

| 交付                      | 玩家能完成什么                                             | 完成条件                                                                                                                      |
| ------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **P0 · 首个可交付章节**   | 选择旅程或漫游，带领 1+11 只雁完成同一条 S0–S6 路线        | 山口、长湖均可通关，旅程可重试，漫游可主动飞行并无失败，12/12 才落脚。水彩、动态音效、基础可访问性和桌面/iPhone/iPad 验收齐备 |
| **P1 · 完整斑头雁故事线** | 完成十次年度迁徙，感受环境变化与路线传统，在第十年完成交接 | 双模式共享年度进度，传统可被玩家感知，新增雁线挑战公平可读，存档迁移及十年流程可验证。鲸线实现在 P2                           |

## 当前起点

- **Web 工程**已有 Vite、严格 TypeScript、Three.js 测试场景、ESLint、Vitest 和 Playwright。现有代码验证画布及 WebGL 2，飞行、触控输入、关卡、存档与音频待开发。GitHub Actions 已有配置，需取得托管 CI 的实际运行证据。
- **素材**已有 `CHR-001`、雁动画及 `LVL-S0` 至 `LVL-S6` 的候选 GLB。`CHR-001` 有素材制作验收记录，七段关卡清单均为 `needs_review`。旧版预览和 Blender 回导可用于筛选资产及理解锚点，Web 镜头、碰撞、许可和实机性能需逐项复核。
- **设计**采用 GDD v2.0 的玩法、输入、镜头和节奏，TDD v1.0 提供架构、数据与测试基线。本工作区没有独立的已接受 ADR，双手操控需要先记录 ADR-009 提案，并在试飞后记录方向映射决策。

## 阶段与依赖

| 阶段                             | 主要工作                                              | 放行条件                                                                                                  |
| -------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **M0 · 工程与契约**              | 固定步长、共享类型、关卡 Schema 与校验入口            | 纯 TS 时钟可重放，暂停可冻结，错误关卡数据会明确报错。[工作包](01-foundation-and-flight.md)               |
| **M1 / P0-A · 飞行实验场**       | 双手输入、主动拖镜、单雁飞行、1+11 同伴、结阵         | 桌面可飞，真实触屏可同时移动并拖镜或结阵，记录两种方向映射试飞结果。[工作包](01-foundation-and-flight.md) |
| **M2 / P0-B · 玩法闭环**         | 能量、凝聚、七类 Zone、救援、双模式、完整检查点、落脚 | 在小型测试地图上跑通成功、两类失败、快照重试和漫游差异。[工作包](02-rules-and-checkpoints.md)             |
| **M3 / P0-C · S0–S6 灰盒**       | 连续世界、双路分叉、教学侧风救援、风场外围和结束段    | 旅程及漫游均有山口与长湖通关回放，低能量可补救，风机预警和碰撞一致。[工作包](03-s0-s6-graybox.md)         |
| **M4 / P0-D · 水彩、音乐与界面** | 资产接入、雁动画、危险反馈、动态音乐、可访问性与画质  | 完整素材版仍可完成灰盒中的操作任务，静音和低画质保留关键信息。[工作包](04-art-audio-and-ui.md)            |
| **M5 · 验收与发布准备**          | 自动化、双模式实机、性能记录、静态构建与恢复路径      | 完成阶段验收矩阵，保留设备和构建证据。[工作包](05-verification-and-release.md)                            |
| **P1 · 十年雁线**                | 年份变体、传统、幕墙/夜灯、年度结算与交接             | 可从第一年完成至第十年，在任一模式推进并正确跨版本恢复。[工作包](06-ten-year-goose.md)                    |

关键顺序为 **固定时钟与共享契约 → 双手飞行与 12 雁结阵 → 小地图规则闭环 → S0–S6 通关 → 正式音画与发布验收**。在 M1/M2 可以做模型导入、素材登记和音乐节拍试验。正式替换某段美术前，先用灰盒锁定该段的通道、触发条件和危险轮廓。

## 工作责任

| 领域       | 交付接口或证据                                                                   |
| ---------- | -------------------------------------------------------------------------------- |
| 核心模拟   | `GameState`、`GameCommand`、`GameEvent`、角色名单、固定 tick、检查点、双模式规则 |
| 输入与镜头 | 固定 `pointerId` 职责、镜头相对方向映射、可独立操作的相机输入、触屏实测          |
| 关卡与数据 | 版本化 `LevelSchema`、唯一 Zone 几何、触发器、段落出口、可达性回放               |
| 美术与音频 | Blender → GLB、运行时资产清单、事件到音画的映射、加载与性能证据                  |
| 测试与集成 | 统一保存回放、设备记录和验收编号。共享契约每次由明确的负责人修改，分支集成前对齐 |

首批执行顺序和待验证设计集中记录在 [实施顺序与待决问题](07-decisions-and-backlog.md)。
