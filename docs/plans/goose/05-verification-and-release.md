# M5 · 验收与发布准备

验收贯穿各阶段。发布前在同一候选构建上汇总自动化、可达性、触屏、画面、声音和实际性能。实测记录包含构建版本、关卡版本、浏览器与系统、机型、画质、路线、模式、实际现象、预期行为以及可复核证据。

## 自动化与实机分工

| 检查                   | 执行方式                                                                                                                                           | 记录                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 类型、风格、单测与构建 | `npm ci`、`npm run check`；阶段 M0 将实际 Schema 校验纳入 CI                                                                                       | 退出结果、构建版本、关卡/资产校验报告                                        |
| 固定步长与快照         | Vitest 规则单测和集成回放；30/60/120 FPS 帧计划，固定世界输入和随机种子（如有）                                                                    | 比较 tick、角色位置/状态、能量、救援剩余时间、相位、路线和事件序列，写明容差 |
| 浏览器 E2E             | 生产构建 `npm run test:e2e`；桌面 Chromium 与横屏 WebKit 模拟覆盖菜单、输入序列、设置、存档和渲染错误                                              | Playwright 日志与失败 trace。真机记录单独提交                                |
| iPhone / iPad Safari   | 横屏双手、系统中断往返、首次音频解锁、长时观察和完整通关。至少在目标 iPhone 和 iPad 各留下完整路线，并在两类设备覆盖双模式操作、S3/S4 风险及安全区 | 录屏、机型、OS/Safari 版本、左右手布局、小屏遮挡、重试和恢复情况             |
| 性能                   | 目标 60 FPS，可评估低档 30 FPS。使用真实设备与实际资产，测首次交互、帧时间、卡顿、内存、Draw Calls 和三角面；长时间暂停再继续及重试后复测          | 基线及优化前后数据。无法取得的指标标明未测                                   |

## 发布门槛

- 四条路线/模式组合、旅程两类失败重试、漫游自动归队、全队落脚均有可复核记录。至少部分覆盖须来自首次玩家独立操作，记录时间与犹豫点供调参。
- 对照灰盒复核素材版危险轮廓、两路可达性、S5 补给与静音完成。若素材版改变风险信息或行进空间，返回关卡配置与验证，不以演出覆盖问题。
- 版本化产物标明关卡版本与资源清单，检查静态入口、资源加载失败重试、旧档/坏档处理及 WebGL 恢复。托管 CI 需获得实际运行结果。QA 记录用“通过、失败、未验证”标注，每项未验证注明影响和复测入口。
