# 实施顺序与待决问题

以下任务均为待实施。仓库已有 TypeScript、Vite 和 WebGL 测试场景，可直接开始 `GameRuntime` 及双手契约工作。任务按可测试的增量拆分，每次包含范围、依赖、输入输出、完成标准、验证记录。稳定主线建立后，多 Agent 工作遵循项目的独立分支与 worktree 约定。

## 可直接拆为首批任务

| 顺序 | 任务                            | 建议范围                                                                        | 合并证据                                                                               |
| ---- | ------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 1    | E02 固定步长与状态接口          | `src/core/`、纯 TS 测试                                                         | 固定 60 Hz，前台追步限制，后台/暂停冻结，世界输入回放                                  |
| 2    | E03 地图版本、运行时校验入口    | `src/levels/`、样例配置、CI                                                     | 初始地图可校验，非法版本、重复 ID、错误引用有定位信息                                  |
| 3    | I01 双手输入契约与 ADR-009 提案 | `src/input/` 与相机输入接口；先写提案并同步共享类型                             | 触点职责、生命周期、镜头/模拟边界和 A/B 试验方案可审阅；Pointer 事件序列覆盖跨区与取消 |
| 4    | S01 + R02 单雁试飞              | `src/simulation/`、`src/species/`、`src/rendering/`，按定好的接口拆成独立工作包 | 单雁转向、滑翔、盘旋与镜头复位可操作，完成首轮 A/B 记录                                |
| 5    | S02 跟随 + S03 结阵             | 队伍、结阵、状态反馈、相应单测                                                  | 12 雁可辨、稳定队形、急转散阵、按住/切换及双手实机验证                                 |
| 6    | S04–S08 规则闭环                | 能量、凝聚、Zone、救援、快照、落脚分别合并                                      | [小型地图验收](02-rules-and-checkpoints.md)的重放、恢复与双模式规则证据                |

E03 可与 E02 的独立部分同期推进，共享类型改动先对齐。素材清点和首个 GLB 导入试验可早做，重点验证轴向、模型尺度、剪辑与双手镜头机位。关卡正式集成依赖对应灰盒段验收。

## 优先决策与原型初值

| 问题                    | 原型起点                                                                                                                  | 何时收敛与验证方法                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 镜头相对移动            | 先试 A 实时映射并限速，再试 B 摇杆按下时锁定基准                                                                          | M1 用相同航线验证持续推杆转镜和回望队尾，以误转、偏航、恢复时间和试玩反馈决定，写入 ADR-009             |
| 拖镜范围与回正          | 偏航约 ±60°、俯视约 35°–65°，先用手动复位                                                                                 | M1 测队尾，在 M3 重测两路入口、风机边缘和领队是否出画；用复位频率和遮挡录像确认范围/回正辅助            |
| 摇杆与结阵              | 死区约 10%，约 90% 进入加速，滑翔约 1 秒。按住为实验默认，提供点按；约 2 秒成阵、1 秒舒展、省力约 1/3、满阵转向速率约 1/2 | M1 测小屏手感与疲劳，M2 验证节能和机动取舍，M3 观察是否全程长按成为优势策略                             |
| 救援时限与触碰损耗      | 时限约 40 秒、接应约 2 秒，风机接触损耗及冷却依配置候选                                                                   | M2 测时钟、中断与重复接触；M3 记录折返接应时间和剩余量，确认保护湿地可达                                |
| 检查点与 A 前的失败提示 | 正式地图先布置 A，重试能量回满作为原型值。A 前可验证从当前关卡起点重开，恢复语义待确认                                    | M2 先验证失败出口，再记录 M3 从 S5 回到 A 的时长、意愿和操作疲劳，决定是否提议 S4 前增设 B              |
| S4 危险边界与预警       | 弧形连续扫掠区、约 3 秒巡航反应窗口、外围约两倍 V 形宽度均按设计验证                                                      | M3 按真实灰盒速度、惯性和镜头测量，M4 素材替换后对照多机位再测                                          |
| 观景与节奏              | GDD 的约 3–5 分钟章节、低压流动段和短提示为初值                                                                           | M3/M4 记录首次通关、无目标停留、低能量提示频率与听觉记忆，避免为追时长删去安全窗口                      |
| Web 素材与性能          | 首段优先使用可确认来源的 GLB 和临时声景，正式资源经审核                                                                   | M4 比较首屏、内存、设备帧时间和 12 雁同屏表现，再决定分区、LOD 与压缩。按目标机复测分辨率、画质和可读性 |

所有玩法参数由一处配置维护，记录初值、实际试验值、机型、结果和决策。GDD v2.0 对右手主动镜头和防误触规则具有优先级。ADR-009 提案须先覆盖四类指针职责、镜头状态、方向映射、镜像和暂停，试玩后补录结果。影响产品规则的变更由项目负责人确认后再更新设计基线。

依据见 [GDD §14–18](../../../Feather_Tide_Gameplay_Design_v2.0.md)、[TDD §13–15](../../../Feather_Tide_Threejs_TDD_v1.0.md)及 [工作契约 §8](../../../AGENTS.md)。
